# Spec: Twirl MVP — May 24 Launch

**Feature ID:** TWIRL-LAUNCH  
**Created:** 2026-05-11  
**Deadline:** 2026-05-24 (13 days)  
**Status:** Active  

---

## Overview

Twirl is a peer-to-peer clothing rental app for sorority women at the University of Arkansas. Lenders list items from their closets; renters browse, book dates, sign a contract, and pay through the app. The 15% commission is Twirl's revenue. The MVP must complete one end-to-end rental on a real iPhone before May 24.

---

## User Stories

### US-01 — Conversation & Real-Time Messaging
**As a renter**, I want to message a lender after submitting a rental request, so that we can coordinate pickup/return without leaving the app.

**As a lender**, I want to receive and reply to messages from renters, so that I can confirm availability and communicate terms.

### US-02 — Unread Badge Accuracy
**As any user**, I want the unread message count on the inbox tab to reflect my actual unread messages (not the other person's), so the badge is meaningful rather than misleading.

### US-03 — Payment Processing
**As a renter**, I want to pay for my rental directly in the app using Apple Pay or a card, so the transaction is secure and the lender is protected.

**As a lender**, I want to receive my payout automatically after the rental completes, so I don't have to chase anyone for money.

### US-04 — Lender Payout Onboarding
**As a lender**, I want to connect my bank account via Stripe before listing an item, so payouts can be sent without manual intervention.

### US-05 — First iPhone Runtime
**As the developer**, I need the app to launch without crashing on a physical iPhone, so I can demo it to founding affiliates and verify the end-to-end flow.

### US-06 — TestFlight Distribution
**As the developer**, I want to distribute the app via TestFlight so founding affiliates (KKG, Pi Phi) can install and test before August rush.

## Functional Requirements

### US-01: Conversation Screen

- Route: `app/conversation/[id].tsx`
- Loads the conversation by `id`, fetches all messages ordered by `created_at ASC`
- Displays messages in a chat bubble layout: sender right (pink), receiver left (cream)
- Realtime subscription via `supabase.channel()` on `messages` table filtered by `conversation_id`
- Input bar pinned to bottom with send button; send inserts a row into `messages`
- On send: update `conversations.last_message` and `last_message_at`
- On open: mark messages as read by clearing `unread_user1` or `unread_user2` based on current user
- Shows item title in header (from `conversations.item_id → items.title`)
- Empty state: "start the conversation — say hi 👋"

### US-02: Unread Count Fix

- Schema truth: `conversations` table has `unread_user1` (int) and `unread_user2` (int), NOT `unread_count`
- `messages.tsx` currently reads `unread_count` — this must change
- Logic: if `user.id === user1_id` → read `unread_user1`; else → read `unread_user2`
- On sending a message: increment the OTHER user's unread column
- On opening a conversation: reset YOUR unread column to 0

### US-03: Payment Processing

- Edge Function `create-payment-intent` must be deployed to Supabase
- Must create two Stripe objects: a PaymentIntent (rental fee) and a SetupIntent (deposit authorization)
- Returns `paymentIntentClientSecret` and `depositIntentClientSecret` to the app
- `contract/[id].tsx` already handles the client-side — the Edge Function is the only missing piece
- After successful payment: update `rentals.status = 'paid'` and `rentals.contract_agreed = true`

### US-04: Stripe Connect Onboarding

- Lenders must have a Stripe Connect Express account before a rental can complete
- Flow: profile screen → "set up payouts" → opens Stripe Connect onboarding URL (generated by Edge Function)
- New Edge Function: `create-connect-account` — creates Stripe Express account, returns onboarding URL
- `profiles` table needs `stripe_account_id` column (nullable varchar)
- Payout triggered by a third Edge Function `capture-and-pay` called when lender marks item returned

### US-05: iPhone Runtime

- Remove any lingering dependency that causes native crash at startup
- Gluestack: CONFIRMED already absent from `package.json` and all source files — no action needed
- Verify `react-native-worklets` (0.5.1) and `react-native-reanimated` (4.1.1) compatibility
- Run `expo prebuild --platform ios` clean, then `pod install`, then launch on device

### US-06: EAS Build

- `eas.json` must be created with `development`, `preview`, and `production` profiles
- `app.json` must have `bundleIdentifier: "com.twirl.app"` under `ios`
- `eas build --platform ios --profile preview` produces a `.ipa` for TestFlight
- CI/CD: `.github/workflows/eas-preview.yml` triggers on push to `main`

## Non-Functional Requirements

- **Latency:** Message delivery < 1s on a real device (Supabase realtime)
- **Security:** Stripe secret key lives only in Edge Function environment variables, never in app bundle
- **Offline:** Auth session persists via AsyncStorage (already implemented)
- **Error surfaces:** Every async operation shows an Alert on failure — no silent failures
- **Accessibility:** Touch targets ≥ 44pt; text contrast meets WCAG AA minimum

## Clarifications

**Q: Does the deposit SetupIntent need to be captured on return, or forfeited automatically?**  
A: Manual capture by admin (Cooper) via Stripe dashboard for now. Automate post-launch.

**Q: What triggers lender payout?**  
A: For MVP, payout is manual via Stripe dashboard. Edge Function `capture-and-pay` is post-May-24 scope unless time permits.

**Q: Is the conversation created at rental request time or separately?**  
A: Already created at request time in `item/[id].tsx → handleRentRequest`. The conversation `id` is already in the DB when the user lands on `/conversation/[id]`.

**Q: Do we need profile photos?**  
A: No. The `👤` placeholder is fine for launch.
